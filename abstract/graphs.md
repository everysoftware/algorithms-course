# Графы

**Граф** — это абстрактная структура данных, которая состоит из множества вершин и рёбер, соединяющих эти вершины.

**Вершина** — это базовый элемент графа, который может представлять объект или точку интереса.

**Ребро** — это связь между двумя вершинами, которая может быть направленной или ненаправленной.

**Цикл** — это последовательность вершин, в которой первая и последняя вершины совпадают, и каждая пара соседних
вершин соединена ребром.

**Путь** — это последовательность вершин, в которой каждая пара соседних вершин соединена ребром, и первая и последняя
вершины могут быть разными.

**Подграф** — это граф, который состоит из части вершин и рёбер исходного графа, то есть подграф может быть получен
путём удаления некоторых вершин и рёбер из исходного графа.

**Изоморфизм графов** — это отношение между двумя графами, при котором существует взаимно однозначное соответствие
между их вершинами и рёбрами, сохраняющее структуру графов.

**Дерево** — это связный ациклический граф, в котором существует ровно один путь между любой парой вершин.

**Лес** — это множество деревьев, то есть связный ациклический граф, который может состоять из нескольких компонент
связности.

# Классификация графов

Ниже представлена логически упорядоченная система классификационных признаков с примерами на
Python (представление через список смежности и не только).

---

## 1. По направленности рёбер

| Тип                                     | Обозначение                                    | Пояснение                                                                                                | Пример матрицы смежности (без весов)    |
|-----------------------------------------|------------------------------------------------|----------------------------------------------------------------------------------------------------------|-----------------------------------------|
| **Неориентированный** (undirected)      | Ребро `{u, v}`                                 | Ребро не имеет направления; `(u,v)` ≡ `(v,u)`. В матрице смежности `A[i][j] == A[j][i]`.                 | `A` симметрична                         |
| **Ориентированный** (directed, digraph) | Дуга `(u → v)`                                 | Движение возможно только от `u` к `v`. Обратное не гарантируется. Матрица, вообще говоря, несимметрична. | `A[i][j]` может быть не равно `A[j][i]` |
| **Смешанный**                           | Комбинация направленных и ненаправленных рёбер | Используется редко; каждое ребро хранит свой признак направленности.                                     | Нетипично для матриц                    |

**Пример на Python**

```python
# Неориентированный граф
undirected = {0: [1, 2], 1: [0, 3], 2: [0, 3], 3: [1, 2]}

# Ориентированный граф (ребра только в одну сторону)
directed = {0: [1, 2], 1: [3], 2: [3], 3: []}
```

---

## 2. По весу рёбер

- **Невзвешенный граф** — каждое ребро имеет одинаковый вес (обычно 1). Рёбра либо есть, либо нет.
- **Взвешенный граф** — каждому ребру приписано число (стоимость, длина, пропускная способность).

Хранение весов в Python:

```python
# Невзвешенный (только соседи)
unweighted = {0: [1, 2], 1: [0, 3], 2: [0, 3], 3: [1, 2]}

# Взвешенный (кортежи: сосед, вес)
weighted = {0: [(1, 5), (2, 2)], 1: [(0, 5), (3, 7)], 2: [(0, 2), (3, 4)], 3: [(1, 7), (2, 4)]}
```

---

## 3. По кратности рёбер и петлям

| Название                        | Петли? | Кратные рёбра? | Описание                                                                                                 |
|---------------------------------|--------|----------------|----------------------------------------------------------------------------------------------------------|
| **Простой граф** (simple graph) | ❌      | ❌              | Максимум одно ребро между парой вершин, петли запрещены. Классический случай для большинства алгоритмов. |
| **Мультиграф** (multigraph)     | ❌      | ✔              | Допускает несколько рёбер между одной парой вершин (параллельные рёбра). Петли запрещены.                |
| **Псевдограф** (pseudograph)    | ✔      | ✔              | Разрешено всё: и петли, и кратные рёбра.                                                                 |

Псевдографы встречаются, например, в автоматных моделях, где переход из состояния в себя — обычное дело.

---

## 4. По связности

### Неориентированные графы

- **Связный граф** — существует путь между любой парой вершин.
- **Несвязный граф** — распадается на компоненты связности (максимальные связные подграфы).
- **Точка сочленения** — вершина, удаление которой увеличивает число компонент связности.
  **Мост** — ребро с тем же свойством.

### Ориентированные графы

- **Сильно связный** — из любой вершины можно дойти до любой другой по направленным путям.
- **Слабо связный** — если заменить все дуги на ненаправленные рёбра, граф становится связным.
- **Компонента сильной связности** — максимальный сильно связный подграф.

### k-связность

- **Вершинно k-связный** (k-vertex-connected) — нужно удалить не менее k вершин, чтобы разорвать связность.
- **Рёберно k-связный** — аналогично для рёбер.
  Используется для оценки надёжности сети.

---

## 5. По наличию циклов

- **Ациклический граф** — нет циклов.
    - Неориентированный ациклический связный граф = **дерево**.
    - Неориентированный ациклический (может быть несвязным) = **лес**.
    - Ориентированный ациклический граф = **DAG** (Directed Acyclic Graph). Фундаментален для планирования задач,
      компиляции, версионирования.
- **Циклический граф** — содержит хотя бы один цикл.

**Пример DAG (Python)**

```python
dag = {
    'A': ['B', 'C'],
    'B': ['D'],
    'C': ['D'],
    'D': []
}
```

---

## 6. По плотности

Плотность графа — отношение числа имеющихся рёбер к максимально возможному числу рёбер (для простого графа).

- **|V|** – число вершин, **|E|** – число рёбер.
- Максимум для неориентированного: **|E_max| = |V|(|V|-1)/2**.
- Максимум для ориентированного: **|E_max| = |V|(|V|-1)**.

Принято считать:

- **Разреженный** (sparse) — |E| ≪ |E_max|, часто |E| = O(|V|) или O(|V|·log |V|).
- **Плотный** (dense) — |E| ≈ |E_max|, например, O(|V|²).

Это важно для выбора представления (матрица смежности для плотных, список для разреженных).

---

## 7. Специальные типы графов

### Полный граф (Complete Graph) \(K_n\)

Каждая пара вершин соединена ребром. |E| = n(n-1)/2 (неориентированный).
Пример: \(K_3\) — треугольник, \(K_4\) — тетраэдр.

### Двудольный граф (Bipartite Graph)

Вершины можно разбить на две доли так, что каждое ребро соединяет вершины из разных долей. Нет рёбер внутри долей.
**Полный двудольный** \(K_{m,n}\) — каждая вершина одной доли связана со всеми вершинами другой доли.

```python
# Полный двудольный K_{2,3}
bipartite = {
    'A': ['X', 'Y', 'Z'],
    'B': ['X', 'Y', 'Z'],
    'X': ['A', 'B'],
    'Y': ['A', 'B'],
    'Z': ['A', 'B']
}
```

### Планарный граф (Planar Graph)

Может быть изображён на плоскости без пересечения рёбер. Классические примеры: деревья, сетки, графы карт.
По теореме Куратовского, граф планарен тогда и только тогда, когда не содержит подграфов, гомеоморфных \(K_5\) или \(K_
{3,3}\).

### Регулярный граф (Regular Graph)

Все вершины имеют одинаковую степень (количество соседей).

- k-регулярный: deg(v) = k для всех v.
- Пример: цикл C_n — 2-регулярный граф. Полный K_n — (n-1)-регулярный.

### Графы, определяемые формой

- **Цикл** (Cycle) \(C_n\) — замкнутая цепочка, где каждая вершина степени 2.
- **Колесо** (Wheel) \(W_n\) — цикл \(C_{n-1}\) плюс центральная вершина, соединённая со всеми.
- **Звезда** (Star) \(S_k\) — одна центральная вершина степени k и k листьев степени 1.
- **Граф‑решётка** (Grid) — вершины образуют прямоугольную таблицу, рёбра только между соседями по вертикали и
  горизонтали.

---

## 8. Дополнительные свойства (часто выделяемые в классы)

Эйлеров граф — содержит эйлеров цикл (проходит по всем рёбрам ровно один раз). Эквивалентно: все вершины имеют чётную
степень и граф связен (кроме изолированных).

Гамильтонов граф — содержит гамильтонов цикл (проходит через каждую вершину ровно один раз). Общего простого критерия
нет, NP-полная задача.

## Итоговая схема классификации

```
Граф
├── По направленности
│   ├── Неориентированный
│   ├── Ориентированный (орграф)
│   └── Смешанный
├── По весу рёбер
│   ├── Невзвешенный
│   └── Взвешенный
├── По кратности и петлям
│   ├── Простой граф
│   ├── Мультиграф
│   └── Псевдограф
├── По связности
│   ├── Связный / Несвязный
│   ├── Сильно связный / Слабо связный (для орграфов)
│   └── k-связный
├── По наличию циклов
│   ├── Ациклический (дерево, лес, DAG)
│   └── Циклический
├── По плотности
│   ├── Разреженный
│   └── Плотный
└── Специальные классы
    ├── Полный (K_n)
    ├── Двудольный / Полный двудольный (K_{m,n})
    ├── Планарный
    ├── Регулярный
    ├── Эйлеров / Гамильтонов
    └── Геометрические: цикл, колесо, звезда, решётка
```

Такая система позволяет быстро охарактеризовать практически любой граф, встречающийся в прикладных и теоретических
задачах, и правильно выбрать алгоритмический инструментарий.

# Представления графов

Граф — это набор **вершин** (узлов), соединённых **рёбрами**. Выбор способа хранения графа в памяти критически влияет на
производительность алгоритмов. Ниже рассмотрены четыре основных представления с примерами на Python, анализом сильных и
слабых сторон, а также сводной таблицей сложности операций.

Все примеры ориентированы на **ориентированный** граф. Для неориентированного графа достаточно при добавлении ребра (u,
v) дублировать его как (v, u).

---

## 1. Список рёбер (Edge List)

**Идея.** Граф хранится как единый список всех рёбер. Каждое ребро — это кортеж `(начало, конец, вес)`. Вершины могут
присутствовать неявно (те, что упомянуты в рёбрах) или храниться отдельным множеством.

**Реализация**

```python
class EdgeListGraph:
    def __init__(self):
        self.edges = []  # список рёбер: (u, v, weight)
        self.vertices = set()  # множество всех вершин

    def add_vertex(self, v):
        self.vertices.add(v)

    def add_edge(self, u, v, weight=1):
        self.vertices.update([u, v])
        self.edges.append((u, v, weight))

    def get_neighbors(self, u):
        """Все вершины, в которые ведут рёбра из u."""
        return [v for (src, v, w) in self.edges if src == u]

    def has_edge(self, u, v):
        return any(src == u and dst == v for src, dst, w in self.edges)
```

**Преимущества**

- Предельная простота — легко сериализовать, передавать, сохранять.
- Естественен для алгоритмов, работающих непосредственно со списком рёбер (например, алгоритм Крускала).
- Не накладывает ограничений на типы вершин, если используется Python (`int`, `str`, любые hashable-объекты).

**Недостатки**

- Поиск всех соседей вершины требует просмотра всех рёбер — **O(E)**.
- Проверка существования ребра также **O(E)**.
- Добавление ребра O(1) (если не требуется поддержание сортировки), но если возникает потребность хранить рёбра
  отсортированными (например, для бинарного поиска), то вставка становится O(E).
- Хранение изолированных вершин требует отдельного множества, иначе они теряются.

**Когда применять**

- Графы с очень малым количеством рёбер.
- Задачи, где граф строится однократно и затем не изменяется.
- Пакетная обработка рёбер без частых запросов соседства.

---

## 2. Матрица смежности (Adjacency Matrix)

**Идея.** Вершины нумеруются индексами `0 … V-1`. Матрица `V×V` хранит веса рёбер: `matrix[i][j] = вес`, если ребро
существует, иначе `0` (или специальное значение). Для невзвешенного графа используют булевы значения.

**Реализация**

```python
class AdjacencyMatrixGraph:
    def __init__(self):
        self.vertices = []  # список меток вершин для сопоставления с индексами
        self.matrix = []  # list of lists

    def _get_index(self, v):
        """Индекс вершины или -1, если отсутствует."""
        try:
            return self.vertices.index(v)
        except ValueError:
            return -1

    def add_vertex(self, v):
        if v not in self.vertices:
            self.vertices.append(v)
            n = len(self.vertices)
            # Добавляем столбец ко всем существующим строкам
            for row in self.matrix:
                row.append(0)
            # Добавляем новую строку
            self.matrix.append([0] * n)

    def add_edge(self, u, v, weight=1):
        self.add_vertex(u)
        self.add_vertex(v)
        i = self.vertices.index(u)
        j = self.vertices.index(v)
        self.matrix[i][j] = weight

    def get_neighbors(self, u):
        i = self._get_index(u)
        if i == -1:
            return []
        return [self.vertices[j] for j, w in enumerate(self.matrix[i]) if w != 0]

    def has_edge(self, u, v) -> bool:
        i, j = self._get_index(u), self._get_index(v)
        if i == -1 or j == -1:
            return False
        return self.matrix[i][j] != 0
```

**Преимущества**

- Проверка существования ребра за **O(1)** — простое обращение по индексам.
- Удобна для плотных графов (где число рёбер близко к V²).
- Хорошо ложится на векторизованные операции (NumPy), что ускоряет целые классы алгоритмов.

**Недостатки**

- Расход памяти **Θ(V²)**. Даже для 1000 вершин при 5000 рёбер занято ~1 МБ, хотя полезной информации немного.
- Медленное добавление/удаление вершин — **O(V²)** из-за изменения размеров матрицы.
- Требует перенумерации вершин в непрерывный диапазон; исходные метки (например, строки) приходится отображать отдельно.
- В чистом виде плохо поддерживает мультиграфы (несколько рёбер между одной парой вершин).

**Когда применять**

- Плотные графы (E ≈ V²).
- Частые запросы «соединены ли u и v?»
- Статический набор вершин либо редкие изменения.

## 3. Список смежности (Adjacency List)

**Идея.** Для каждой вершины хранится коллекция её исходящих соседей. Обычно это словарь, где ключ — вершина, значение —
список пар `(сосед, вес)`. В невзвешенном случае — просто список соседей.

**Реализация**

```python
class AdjacencyListGraph:
    def __init__(self):
        self.adj = {}  # вершина -> список (сосед, вес)

    def add_vertex(self, v):
        if v not in self.adj:
            self.adj[v] = []

    def add_edge(self, u, v, weight=1):
        self.add_vertex(u)
        self.add_vertex(v)
        self.adj[u].append((v, weight))

    def get_neighbors(self, u):
        return self.adj.get(u, [])

    def has_edge(self, u, v) -> bool:
        return any(neighbor == v for neighbor, _ in self.adj.get(u, []))
```

**Преимущества**

- Экономия памяти: требуется **Θ(V + E)** места — идеально для разреженных графов.
- Перебор всех соседей вершины пропорционален её степени, в среднем очень быстр.
- Динамическое добавление вершин и рёбер — O(1) (в среднем для словаря).
- Легко определить степень вершины: `len(self.adj[v])`.

**Недостатки**

- Проверка наличия конкретного ребра (u, v) требует сканирования списка соседей u — **O(deg(u))**, в худшем случае O(V).
- В наихудшем случае (полный граф) требования к памяти сравниваются с матрицей, но с бо́льшими накладными расходами на
  объекты Python.

**Когда применять**

- Большинство реальных графов (социальные сети, веб-графы, дорожные карты) — они разрежены.
- Когда важна эффективность обхода соседей (BFS, DFS, алгоритм Дейкстры и т.д.).

---

## 4. Объектно-ориентированное представление

**Идея.** Вершины и рёбра моделируются как полноценные объекты. Вершина может хранить ссылки на инцидентные рёбра (или
соседей), ребро — ссылки на конечные вершины и вес. Такой подход даёт максимальную гибкость: можно добавлять методы,
вычисляемые свойства, наследовать классы для специфических графовых структур.

**Реализация**

```python
from __future__ import annotations


class Node:
    """Вершина графа."""

    def __init__(self, key):
        self.key = key
        self.edges: list[Edge] = []  # исходящие рёбра
        # при необходимости можно хранить и входящие

    def add_edge(self, edge: Edge) -> None:
        self.edges.append(edge)


class Edge:
    """Ребро графа."""

    def __init__(self, from_node: Node, to_node: Node, weight: float = 1.0):
        self.from_node = from_node
        self.to_node = to_node
        self.weight = weight


class Graph:
    """Контейнер для вершин и рёбер."""

    def __init__(self):
        self.nodes: dict[str, Node] = {}  # key -> Node

    def add_node(self, key) -> Node:
        if key not in self.nodes:
            self.nodes[key] = Node(key)
        return self.nodes[key]

    def add_edge(self, from_key, to_key, weight=1.0):
        from_node = self.add_node(from_key)
        to_node = self.add_node(to_key)
        edge = Edge(from_node, to_node, weight)
        from_node.add_edge(edge)
        # Для неориентированного графа to_node.add_edge(...) симметрично

    def get_neighbors(self, key):
        node = self.nodes.get(key)
        if not node:
            return []
        return [(edge.to_node.key, edge.weight) for edge in node.edges]

    def has_edge(self, from_key, to_key) -> bool:
        node = self.nodes.get(from_key)
        if not node:
            return False
        return any(edge.to_node.key == to_key for edge in node.edges)
```

**Пример создания графа с циклами и изолированной вершиной:**

```python
g = Graph()
g.add_edge('A', 'B', 5)
g.add_edge('B', 'C', 7)
g.add_edge('C', 'A', 2)
g.add_node('X')  # изолированная вершина

# Цикл: G ссылается на A, A ссылается на G
g.add_edge('A', 'G')
g.add_edge('G', 'A')
```

**Преимущества**

- Высокая читаемость и интуитивность — модель близка к реальному понятию графа.
- Легко расширяется: можно добавить методы проверки циклов, алгоритмы прямо в классы, произвольные атрибуты (цвет,
  метки, координаты).
- Естественная работа с мультиграфами и гиперграфами.
- Позволяет реализовать «ленивое» вычисление свойств (кеширование степеней и т.п.).

**Недостатки**

- Большие накладные расходы памяти из-за множества объектов Python.
- Операции могут быть медленнее из-за косвенных обращений.
- Проверка ребра между двумя вершинами всё равно линейна по степени, как и в обычном списке смежности.
- Требует поддержки циклических ссылок (сборщик мусора справляется, но иногда нужны слабые ссылки).

**Когда применять**

- Прототипирование, учебные проекты, когда важна наглядность.
- Графовые структуры с богатой семантикой и дополнительными методами.
- Предметно-ориентированные библиотеки и фреймворки.

| Операция                  | Список рёбер                             | Матрица смежности                     | Список смежности                     | ООП (аналог списка смежности)        |
|---------------------------|------------------------------------------|---------------------------------------|--------------------------------------|--------------------------------------|
| Память                    | Θ(E)                                     | Θ(V²)                                 | Θ(V + E)                             | Θ(V + E) + накладные на объекты      |

- В Python из-за динамической природы «O(1)» для операций со словарями амортизированное.

## Рекомендации по выбору

- **«Золотой серединой» для большинства практических задач является список смежности** (словарь списков). Он даёт
  отличный баланс между памятью и скоростью обходов.
- **Матрицу смежности** выбирают, когда граф плотный и критически важна мгновенная проверка наличия ребра, либо когда
  алгоритм выражен в матричной форме (например, алгебраические методы).
- **Список рёбер** наилучшим образом подходит для потоковой обработки и алгоритмов, работающих непосредственно с
  рёбрами, особенно если граф редко модифицируется после построения.
- **Объектно-ориентированный стиль** применяйте на ранних этапах проектирования, в учебных примерах и в тех случаях,
  когда графовый домен требует богатой инкапсуляции и наследования.

Аккуратный выбор представления на старте избавит от переписывания кода при росте объёма данных и позволит реализовать
сложные алгоритмы максимально эффективно.

# Базовые алгоритмы на графах

## 1. Как мы храним граф

**Список смежности** — самый гибкий способ.

```python
graph = {0: [1, 2], 1: [2], 2: [0, 3], 3: []}  # невзвешенный
wgraph = {0: [(1, 4), (2, 1)], 1: [(2, 2)], 2: [(3, 5)]}  # взвешенный
```

Мы используем словарь, где ключ — вершина, значение — список соседей (или пар `(сосед, вес)`). Это удобно для обходов.

## 2. Обход в глубину (DFS)

### Наглядное объяснение

Представьте лабиринт. Вы идёте по коридору, пока не упрётесь в тупик или в уже посещённую комнату, затем возвращаетесь к
последней развилке и пробуете следующий коридор.
DFS **«ныряет»** вглубь графа, запоминая путь с помощью стека (реального или рекурсивного).
**Почему посещаются все вершины компоненты?**
Из-за структуры стека: когда мы «откатываемся», мы обязательно обрабатываем все ответвления, потому что каждое ребро из
текущей вершины будет рассмотрено до возврата. Рекурсия автоматически запоминает контекст.

### Код

```python
def dfs(graph, v, visited=None):
    if visited is None:
        visited = set()
    visited.add(v)
    print(v, end=' ')  # действие при заходе
    for neighbor in graph.get(v, []):
        if neighbor not in visited:
            dfs(graph, neighbor, visited)  # "ныряем" глубже
    return visited
```

**Визуализация на графе** `{0:[1,2], 1:[2], 2:[0,3], 3:[]}`:
Порядок захода: 0 → 1 → 2 → 3 (конкретный порядок зависит от порядка соседей). После тупика (3) возвращаемся к 2, потом
к 0, проверяем уже посещённые — всё.

## 3. Обход в ширину (BFS)

### Наглядное объяснение

Представьте, что вы бросаете камень в воду. Волны расходятся кругами. BFS посещает вершины **по слоям**: сначала сам
старт, потом все его соседи, потом соседи соседей, и так далее.
Для этого используется **очередь**: когда мы достаём вершину, мы добавляем всех её ещё не посещённых соседей в конец
очереди. Это гарантирует, что вершины будут обработаны в порядке увеличения расстояния от старта.
**Почему находятся кратчайшие пути в невзвешенном графе?**
Потому что мы посещаем вершины в порядке возрастания расстояния: сначала все на расстоянии 1, потом 2 и т.д. Как только
мы впервые встречаем целевую вершину, расстояние до неё минимально.

### Код

```python
from collections import deque


def bfs_shortest_path(graph, start, target):
    visited = set()
    queue = deque([(start, 0)])  # (вершина, расстояние)
    visited.add(start)
    while queue:
        v, dist = queue.popleft()
        if v == target:
            return dist
        for neighbor in graph.get(v, []):
            if neighbor not in visited:
                visited.add(neighbor)
                queue.append((neighbor, dist + 1))
    return -1
```

## 4. Поиск компонент связности

### Наглядное объяснение

Если граф неориентированный, то группы вершин, где из любой можно дойти до любой, образуют **компоненты связности**. Мы
просто запускаем DFS (или BFS) из каждой ещё не посещённой вершины — каждый обход «вычерчивает» целиком одну
компоненту.
Почему это работает? Потому что между вершинами одной компоненты существует путь, и обход гарантированно посетит все
такие вершины (иначе путь обрывался бы на непосещённой вершине, что противоречит связности). А если вершина не попала в
уже найденные компоненты, значит она принадлежит новой.

### Код

```python
def connected_components(graph):
    visited = set()
    components = []
    for v in graph:
        if v not in visited:
            comp = []
            stack = [v]
            visited.add(v)
            while stack:
                node = stack.pop()
                comp.append(node)
                for neighbor in graph[node]:
                    if neighbor not in visited:
                        visited.add(neighbor)
                        stack.append(neighbor)
            components.append(comp)
    return components
```

## 5. Топологическая сортировка (DAG)

Нужно выстроить вершины в линейную цепочку так, чтобы все стрелки (рёбра) шли слева направо.
Применяется в планировании задач с зависимостями.

### 5.1. Алгоритм Кана (BFS)

#### Наглядное объяснение

Ищем вершины, у которых **нет входящих рёбер** (нет зависимостей) — их можно выполнить первыми. Помещаем их в очередь.
Далее «удаляем» такие вершины из графа (мысленно), уменьшая при этом количество входящих рёбер у их соседей. Если у
соседа входящая степень стала 0, он становится доступен для выполнения.
**Почему это даёт корректный порядок?** На каждом шаге мы ставим вершину, все зависимости которой уже удовлетворены (они
уже в результате). Мы никогда не поставим вершину раньше её предшественника. Если в конце остались вершины с ненулевой
входящей степенью — в графе цикл.

#### Код

```python
def kahn_topological_sort(graph):
    indegree = {v: 0 for v in graph}
    for v in graph:
        for nb in graph[v]:
            indegree[nb] += 1

    q = deque([v for v in indegree if indegree[v] == 0])
    res = []
    while q:
        u = q.popleft()
        res.append(u)
        for nb in graph[u]:
            indegree[nb] -= 1
            if indegree[nb] == 0:
                q.append(nb)
    if len(res) != len(graph):
        raise ValueError("Cycle detected")
    return res
```

### 5.2. DFS с временами выхода

#### Наглядное объяснение

Если рекурсивно погружаться в зависимости задачи (например, задачу можно выполнить только после завершения всех её
подзадач), то момент, когда мы полностью обработали вершину и её потомков, — это момент «готовности» этой вершины. Чем
позже мы вышли из вершины, тем раньше её следует поставить в финальном порядке (если смотреть справа налево).
**Почему работает?** Для любого ребра `u → v` DFS выйдет из `v` раньше, чем из `u` (потому что `v` будет обработан во
время вызова `dfs(u)`). Значит, при добавлении вершины в список после обработки всех потомков мы получаем обратный
топологический порядок. Развернув список, получаем правильный.

#### Код

```python
def dfs_topological_sort(graph):
    visited = set()
    order = []

    def dfs(v):
        visited.add(v)
        for nb in graph.get(v, []):
            if nb not in visited:
                dfs(nb)
        order.append(v)  # пост-обработка

    for v in graph:
        if v not in visited:
            dfs(v)
    return order[::-1]
```

## 6. Кратчайшие пути во взвешенном графе

### 6.1. Алгоритм Дейкстры (неотрицательные веса)

#### Наглядное объяснение

Представьте, что из начальной точки расползается фронт, как при наводнении. Сначала ближайшие города затопляются на
расстоянии, равном длине ребра. Мы всегда берём **самый близкий ещё не обработанный город** и расслабляем его соседей:
может, через него путь короче, чем известный ранее?
Используем **min-кучу**, чтобы быстро извлекать вершину с минимальной текущей оценкой расстояния.
**Почему алгоритм корректен?** Когда мы извлекаем вершину из кучи, её текущее расстояние уже окончательное: любой другой
путь мог бы идти только через ещё не обработанные вершины, расстояния до которых не меньше (веса неотрицательны!),
значит, и полный путь был бы не меньше.
**Почему нельзя с отрицательными весами?** Потому что «позже» мы могли бы найти путь, который включает отрицательное
ребро и уменьшил бы расстояние до уже обработанной вершины, нарушив принцип «минимальное из кучи — окончательное».

#### Код

```python
import heapq


def dijkstra(graph, start):
    dist = {v: float('inf') for v in graph}
    dist[start] = 0
    pq = [(0, start)]
    while pq:
        d, u = heapq.heappop(pq)
        if d > dist[u]:
            continue
        for v, w in graph.get(u, []):
            if dist[u] + w < dist[v]:
                dist[v] = dist[u] + w
                heapq.heappush(pq, (dist[v], v))
    return dist
```

### 6.2. Алгоритм Беллмана-Форда

#### Наглядное объяснение

Дейкстра не работает с отрицательными весами. Беллман-Форд «повторяет релаксацию всех рёбер» `(V-1)` раз. Почему именно
столько? Потому что кратчайший путь в графе без отрицательных циклов содержит не более `V-1` рёбер. Каждая итерация
увеличивает длину рассматриваемых путей на одно ребро. После `k` итераций мы знаем кратчайшие пути, содержащие не более
`k` рёбер.
После завершения делается ещё один проход: если где-то можно улучшить расстояние, значит существует отрицательный цикл (
можно бесконечно уменьшать путь).
**Корректность:** Индукция по количеству рёбер. Изначально известны расстояния для путей из 0 рёбер (только до старта).
На каждом шаге релаксация распространяет правильные значения для путей длины `k+1` из уже корректных путей длины `k`.

#### Код

```python
def bellman_ford(vertices, edges, start):
    dist = {v: float('inf') for v in vertices}
    dist[start] = 0
    for _ in range(len(vertices) - 1):
        for u, v, w in edges:
            if dist[u] != float('inf') and dist[u] + w < dist[v]:
                dist[v] = dist[u] + w
    # Проверка отрицательного цикла
    for u, v, w in edges:
        if dist[u] != float('inf') and dist[u] + w < dist[v]:
            raise ValueError("Negative cycle")
    return dist
```

### 6.3. Алгоритм Флойда–Уоршелла (все пары)

#### Наглядное объяснение

Мы строим матрицу расстояний и постепенно разрешаем использовать всё новые промежуточные вершины. На `k`-м шаге мы
отвечаем на вопрос: «каков кратчайший путь из `i` в `j`, если разрешено использовать вершины из множества
`{0,1,...,k}`?»
Переход: либо новый кратчайший путь не использует вершину `k` (тогда берём значение с предыдущего шага), либо
использует, и тогда он состоит из кратчайшего пути из `i` в `k` и из `k` в `j` (оба используют вершины `<k`). Отсюда
формула:
`dist[i][j] = min(dist[i][j], dist[i][k] + dist[k][j])`.
**Почему это работает?** Динамическое программирование: мы рассматриваем оптимальную структуру и заполняем матрицу по
слоям. Порядок перебора (цикл по `k` снаружи) важен, чтобы на шаге `k` использовались уже оптимальные пути с
промежуточными вершинами до `k-1`. После обработки всех `k` получаем кратчайшие пути для любых промежуточных вершин.

#### Код

```python
def floyd_warshall(vertices, edges):
    n = len(vertices)
    dist = {u: {v: float('inf') for v in vertices} for u in vertices}
    for v in vertices:
        dist[v][v] = 0
    for u, v, w in edges:
        dist[u][v] = w
    for k in vertices:
        for i in vertices:
            for j in vertices:
                if dist[i][k] + dist[k][j] < dist[i][j]:
                    dist[i][j] = dist[i][k] + dist[k][j]
    return dist
```

## 7. Минимальное остовное дерево (MST)

Нужно выбрать минимальный по сумме весов набор рёбер, который связывает все вершины (без циклов).

### 7.1. Алгоритм Прима

#### Наглядное объяснение

Похож на Дейкстру, но критерий выбора не общее расстояние от старта, а **вес ребра, которым вершина подключается к уже
построенному дереву**.
Мы растущее дерево «втягивает» в себя ближайшую внешнюю вершину, добавляя лёгкое соединительное ребро. Для этого
поддерживаем min-кучу, где ключ — минимальный вес ребра, соединяющего ещё не включённую вершину с деревом.
**Корректность** следует из свойства «разреза»: если на каждом шаге выбирать минимальное ребро, пересекающее разрез
между деревом и остальным графом, получится MST. Прим делает именно это.

#### Код

```python
def prim_mst(graph, start):
    visited = set()
    mst = []
    total = 0
    pq = [(0, start, None)]  # (вес_до_дерева, вершина, откуда)
    while pq:
        w, u, prev = heapq.heappop(pq)
        if u in visited:
            continue
        visited.add(u)
        if prev is not None:
            mst.append((prev, u, w))
            total += w
        for v, weight in graph.get(u, []):
            if v not in visited:
                heapq.heappush(pq, (weight, v, u))
    return mst, total
```

### 7.2. Алгоритм Краскала

#### Наглядное объяснение

Отсортируем все рёбра от самого лёгкого к самому тяжёлому. Идём по ним и **жадно** добавляем ребро в MST, если оно не
создаёт цикл.
Почему это можно делать? Потому что если мы дошли до ребра `e`, то все более лёгкие рёбра уже рассмотрены. Если `e`
соединяет две разные компоненты, то оно является минимальным ребром, пересекающим разрез между этими компонентами, а
значит, оно обязано войти в какой-то MST (по свойству разреза). Проверка на циклы эффективно выполняется с помощью *
*системы непересекающихся множеств (DSU)**.

#### Код

```python
class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.rank = [0] * n

    def find(self, x):
        if self.parent[x] != x:
            self.parent[x] = self.find(self.parent[x])
        return self.parent[x]

    def union(self, x, y):
        xr, yr = self.find(x), self.find(y)
        if xr == yr: return False
        if self.rank[xr] < self.rank[yr]:
            self.parent[xr] = yr
        elif self.rank[xr] > self.rank[yr]:
            self.parent[yr] = xr
        else:
            self.parent[yr] = xr
            self.rank[xr] += 1
        return True


def kruskal_mst(vertices, edges):
    dsu = DSU(len(vertices))
    edges_sorted = sorted(edges, key=lambda e: e[2])
    mst = []
    total = 0
    for u, v, w in edges_sorted:
        if dsu.union(u, v):
            mst.append((u, v, w))
            total += w
    return mst, total
```

## 8. Заключение

Каждый алгоритм имеет чёткое обоснование:

- **Обходы (DFS/BFS)** — систематическое исследование всех рёбер через стек/очередь, с гарантией посещения всех
  достижимых вершин.
- **Топологическая сортировка** — либо удаление вершин без входящих рёбер (Кан), либо пост-обработка в DFS (свойство
  времени выхода).
- **Дейкстра** — жадный выбор ближайшей вершины, корректность на неотрицательных весах благодаря неубыванию оценок.
- **Беллман-Форд** — наращивание длины пути, позволяющее отрицательные веса, с проверкой циклов.
- **Флойд-Уоршелл** — динамическое программирование с наращиванием множества разрешённых промежуточных вершин.
- **MST (Прим, Краскал)** — свойство разреза гарантирует, что жадный выбор безопасен.

Теперь вы не только знаете, как реализовать алгоритмы, но и понимаете их внутреннюю механику и причины
работоспособности.
